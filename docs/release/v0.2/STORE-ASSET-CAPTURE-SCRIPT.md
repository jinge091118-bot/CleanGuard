# CleanGuard V0.2 商店素材拍摄脚本

**状态**：待真机到位后执行
**用途**：产出 Play 商店所需的 1024×500 特色图与 ≥2 张手机截图
**配套文档**：`STORE-LISTING.md` §5

---

## 0. 拍摄前的硬性要求

### 素材规格

| 素材 | 规格 | 说明 |
|---|---|---|
| 应用图标 | 512×512 PNG | 32 位 PNG，无 alpha 通道，文件 < 1 MB |
| 特色图 | 1024×500 PNG 或 JPG | 无 alpha 通道，< 15 MB |
| 手机截图 | 16:9 或 9:16，每边 ≤ 3840 px | 至少 2 张，最多 8 张 |

### 数据准备（这一步决定截图质量）

**必须用无隐私的演示数据。** 不能用任何真实照片、真实文件名或真实路径。

| 准备项 | 做法 |
|---|---|
| 演示图片 | 生成纯色/几何图形图片，放在 `Pictures/DemoMedia/`，文件名用 `sample_01.jpg` 这类中性命名 |
| 演示视频 | 用任意测试视频，或跳过（截图不需要真视频） |
| 演示音频 | 跳过 |
| 演示 APK | 可选，放一个任意 APK 增强「APK 洞察」页的真实感 |
| 重复文件 | 复制几份同内容的图片，命名 `dup_sample_0N.jpg`，用于演示重复确认页 |
| 旧文件 / 大文件 | 生成若干不同大小、不同修改时间的文件，让分类结果看起来自然 |
| 应用占用 | 正常安装几个常用应用即可（真实应用名无隐私问题） |

> **判断标准**：截图里出现的任何字符串，都不能对应你设备上的真实私人内容。

### 系统状态

| 项目 | 要求 | 理由 |
|---|---|---|
| 语言 | 中文（简体） | 与商店文案语言一致 |
| 主题 | 跟随系统（浅色或深色） | 建议浅色，更符合工具类应用的常见观感 |
| 状态栏 | 干净（无开发者通知、无异常图标） | 减少杂乱 |
| 导航栏 | 保留或隐藏都行，全屏更干净 | 建议保留系统导航栏 |
| 动画 | 关闭「移除动画」会影响录屏，但截图不受影响 | — |

## 1. 拍摄清单（按优先级）

### S1 — 首页总览（**必拍，封面图**）

**这张决定用户是否点进来。** 必须一眼看懂「这是个存储分析工具」。

| 步 | 操作 |
|---|---|
| 1 | 完成媒体权限授权 |
| 2 | 执行一次「安全体检」，等扫描完成 |
| 3 | 回到首页 |
| 4 | 确认页面显示：设备容量条、已用/可用空间、分类概览卡片 |

**画面必须包含**：
- 应用标题栏「CleanGuard」
- 设备容量占用条（带数字）
- 「空间分类」或分类统计区
- 「开始安全体检」按钮

**构图要点**：截全屏即可，但首页如果有折叠内容，先展开分类概览再截。

---

### S2 — 扫描结果与建议（**必拍**）

这是最能体现「可解释」差异的一张。

| 步 | 操作 |
|---|---|
| 1 | 从首页点「查看详细结果」进入结果页 |
| 2 | 向下滚动到有建议条目的位置 |
| 3 | 截取包含「建议查看」标签与理由说明的区间 |

**画面必须包含**：
- 建议条目的**理由说明**（这是核心卖点）
- 「建议查看 · HIGH」这类**优先级标签**（展示分级）
- 与风险等级区分的视觉元素（如果有）

> ⚠️ **不要**截到能体现「一键清理」的按钮。CleanGuard 没有这个功能，但截图里若出现类似观感会造成误导。

---

### S3 — 重复文件确认页（强烈建议）

这张展示「由你确认」。

| 步 | 操作 |
|---|---|
| 1 | 进入「重复文件」页，等哈希计算完成 |
| 2 | 截取能同时看到：重复组列表 + 每个文件的复选框 **全部未选中** 的画面 |

**画面必须包含**：
- 复选框**默认未选中**的状态（这是关键卖点）
- 「默认没有选择任何文件」或等义提示
- 「建议保留最新/最早」的提示（体现是建议而非自动决定）

---

### S4 — 清理前确认页（建议）

展示双重确认机制。

| 步 | 操作 |
|---|---|
| 1 | 在结果页选中 1–2 个 SAFE 项，进入清理详情 |
| 2 | 截取确认页，包含风险等级与允许动作说明 |

**画面必须包含**：
- 风险等级标识
- 说明这是「移入系统回收站」而非永久删除
- 保留时长由系统决定的提示

---

### S5 — 权限中心（**建议拍**）

这张能显著降低审核疑虑，也能证明最小权限。

| 步 | 操作 |
|---|---|
| 1 | 设置 → 打开权限中心 |
| 2 | 截取完整页面 |

**画面必须包含**：
- 每项权限的**状态**（已授权/未授权）
- 每项权限的**用途**说明
- 每项权限**未授权时的影响**说明
- 隐私说明区的完整内容（包含本次新增的分享/预览披露与哈希说明）

---

### S6 — 空间趋势（可选）

| 步 | 操作 |
|---|---|
| 1 | 在有 2 次以上扫描历史后进入空间趋势页 |
| 2 | 截取趋势图 |

需要至少两次扫描才能有数据，拍摄前先扫两次。

---

### S7 — 应用占用（可选）

| 步 | 操作 |
|---|---|
| 1 | 进入「空间洞察 → 应用占用」 |
| 2 | 若已授权使用情况访问，截取列表 |

需要先在系统设置里手动开启使用情况访问。

## 2. 特色图（1024×500）制作

### 布局

1024×500 是横幅比例。文字与图形都要在**小尺寸下可读** —— 用户在商店列表里看到的是缩略图。

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│   CleanGuard                                    [图形] │
│   看懂你的存储占用                          ┌─────────┐ │
│   只处理你确认的内容                        │ 容量条  │ │
│                                            │  已用    │ │
│                                            │  52%     │ │
│                                            └─────────┘ │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### 制作要求

| 项目 | 要求 |
|---|---|
| 主文案 | 「看懂你的存储占用」+「只处理你确认的内容」两行足够 |
| 字号 | 主标题在 1024×500 画布上不小于 48px（缩略图才看得清） |
| 配色 | 用应用主色；避免大面积深色或渐变 |
| 图形 | 可截取首页截图片段，但**必须裁掉所有真实数据**，用演示数据 |
| 安全区 | 四周留 40px 以上边距，避免被裁切 |

### 简化方案

如果来不及做复杂设计，把 S1 首页截图作为底图，叠加深色半透明蒙版 + 白色文字，是最稳妥的做法。

## 3. 图标（512×512）导出

### 来源

应用图标在 `app/src/main/res/mipmap-*/ic_launcher.png` / `ic_launcher_foreground.xml`（自适应图标）。

### 导出步骤

1. 用 Android Studio 的 **Image Asset** 工具，或
2. 用 `aapt` / 脚本从 APK 提取，或
3. 在设备上安装后截图图标区域

### 要求

| 项目 | 要求 |
|---|---|
| 尺寸 | 512×512 |
| 格式 | 32 位 PNG（带 alpha） |
| 形状 | **不要**自己加圆角或阴影 —— Play 会自动裁切成各种形状 |
| 背景 | 图标应自带背景（自适应图标的全屏背景层），否则在不同主题下会变形 |

> Play 会把 512×512 图标裁成圆形、方形、squircle 等多种形状供系统使用。设计时确保**中心主体在正方形中央 66% 区域内**，这样任何形状都不会切到主体。

## 4. 拍摄技巧

| 技巧 | 原因 |
|---|---|
| 用 `adb shell screencap` 而非系统截图 | 可指定输出路径，无需手动裁剪状态栏 |
| 保持设备原生分辨率 | 后期缩放会模糊 |
| 关闭自动旋转 | 避免拍到横屏 |
| 拍前清空通知栏 | 减少杂乱 |
| 同一批次拍完所有图 | 保持视觉风格一致（同样的亮度、主题、状态栏） |

### 抓屏命令

```bash
adb shell screencap -p /sdcard/shot_01.png
adb pull /sdcard/shot_01.png ./screenshots/
```

## 5. 拍摄后自检

上传前逐张检查：

- [ ] 没有任何真实照片、真实文件名、真实路径
- [ ] 没有出现「一键清理」类按钮或观感
- [ ] 没有显示含真实联系信息的内容
- [ ] 文字在缩略图尺寸下仍可读（缩到 25% 看一眼）
- [ ] 没有系统通知、开发者角标、异常图标
- [ ] 截图顺序合理：第一张必须是首页（会成为封面）

---

## 6. 拍摄完毕后

1. 清理设备上的演示数据目录（`Pictures/DemoMedia/` 等）
2. 删除设备上的临时截图文件
3. 把成图存入仓库外的位置（或仓库内的 `store-assets/` 目录，加进 `.gitignore` 或按需提交）
4. 在 `STORE-LISTING.md` §5 更新素材状态表

---

## 7. 与真机需求的合并

拍摄需要真机，R2 手测和 R3 性能采集也需要真机。**建议一次设备到位，把三件事都做完**：

| 顺序 | 事项 | 参考文档 | 预计耗时 |
|---|---|---|---|
| 1 | 设备身份核实（确认是物理机） | `MANUAL-SCENARIO-SCRIPTS.md` 通用前置条件 | 10 分钟 |
| 2 | 拍摄商店素材 | 本文档 | 1–2 小时 |
| 3 | 执行 12 个手测场景 | `MANUAL-SCENARIO-SCRIPTS.md` | 半天 |
| 4 | 采集 R3 性能数据（10k/50k/100k） | `R3-PERFORMANCE-TEST-PLAN.md` | 半天到一天 |

**拍摄放在最前面**，因为它不依赖扫描数据集，做完就彻底解锁了 R4 的最后一项。
