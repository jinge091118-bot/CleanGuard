# CleanGuard 源码公开与版权策略

**状态**：已决策（2026-10-26）
**适用范围**：CleanGuard 全部公开仓库内容与未来商业化方向

---

## 1. 结论

CleanGuard 采用**「源码公开 + 专有许可」**模式：

- 源码在 GitHub 上公开可读，用于审阅、评估、安全报告与文档引用
- 通过仓库根目录的 `LICENSE` 文件授予**仅供查看与审计**的许可，保留全部其他权利
- **不是开源项目**，未授予任何 OSI 批准的开源许可证
- `CleanGuard` 名称、Logo 与品牌标识保留为商标

**这一决策同时满足「公开透明」与「保护商业化空间」两个目标。** 源码可见不等于开源，许可证才是决定法律边界的那道闸门。

---

## 2. 事实依据

### 2.1 法律层面

| 问题 | 结论 | 依据 |
|---|---|---|
| 公开源码是否等于开源？ | **不等于** | OSI 定义要求附带 OSI 批准的开源许可证。官方 FAQ 明确：*"simply making source code visible does not make software open source... Visibility is not permission."* |
| 无许可证文件会怎样？ | 默认**保留所有权利**（All Rights Reserved） | 版权法自动生效。GitHub 在无许可证时显示 "All rights reserved" |
| 公开是否影响版权？ | **不影响，反而更强** | 版权创作即产生。公开源码确立作者身份与创作时间，是争议时的证据链 |
| 公开是否影响收费能力？ | **不影响** | Play 开发者协议第 4.4 条：Google 不取得你产品的任何知识产权。收费取决于产品价值与用户规模，与源码可见性无关 |

### 2.2 技术层面（对本项目的实际保护力评估）

这一点比法律层面更重要，因为 CleanGuard 是**纯本地应用**：

| 保护手段 | 实际效果 |
|---|---|
| APK 混淆（ProGuard/R8） | 中等。Release 构建已启用 `isMinifyEnabled = false`，当前**未开启混淆** |
| APK 反编译（JADX 等） | **无效**。任何人下载 APK 都能得到接近源码的逻辑。CleanGuard 无 NDK 代码，无服务端，全部逻辑在客户端 |
| 源码保密（GitHub 私有） | **有限**。仅延缓抄袭，不构成屏障 |
| 商标保护 | **强**。品牌、商店页、评分积累无法被复制 |
| 专有许可证 + DMCA | **中强**。为追责提供明确依据，让未经许可的再分发有可主张的权利基础 |

**结论**：由于 APK 本就可反编译，把全部工程资源投入到「隐藏源码」的实际收益有限。因此选择「公开但明确设限 + 保留全部权利 + 保留商标」，而非投入成本去维持一个无法真正保密的私有仓库。

### 2.3 已公开的历史

2026-10-26 之前，`master` 分支已公开 V0.1 基线，其中包含：

- 111 个 `.kt` / `.java` 源文件
- `app/src/main/assets/safety_rules_v1.json`（安全规则定义）
- `app/src/main/AndroidManifest.xml`（权限声明）
- `app/proguard-rules.pro`

V0.2 相对 V0.1 的增量为 118 个文件、7,351 行新增代码，包含增量扫描引擎、推荐引擎、重复文件确认、恢复中心等核心能力。

## 3. 已实施的具体措施

| 措施 | 位置 | 作用 |
|---|---|---|
| 专有许可证 | 仓库根目录 `LICENSE` | 授予查看与审计许可；保留使用、修改、再分发、衍生作品的所有权利；保留商标 |
| 双语版权声明 | `README.md` 顶部 | 任何人打开仓库第一屏即可看到「非开源」声明 |
| 仓库描述 | GitHub 仓库设置 | 标注「源码公开供审阅，专有许可，非开源项目」 |
| 仓库标签 | GitHub topics | `proprietary`、`not-open-source` |
| 密钥隔离 | `.gitignore` | 排除 `*.jks`、`*.keystore`、`*.p12`、`*.pfx`、`key.properties`、`local.properties` |

### 密钥审计结果（2026-10-26）

推送前逐项核实，**无任何凭据泄露**：

- 被跟踪的密钥类文件：仅 `key.properties.example`（占位模板，密码为 `SET_...` 假值）
- `local.properties`：未跟踪
- `app/src/main/` 下的硬编码凭据（api_key / secret / password / token / 私钥头 / GitHub token 格式）：0 命中

## 4. 未来商业化的可行性

已确认：源码公开**不会阻断**以下任何模式。

| 模式 | 是否可行 | 说明 |
|---|---|---|
| 免费 + 应用内购买 Pro | ✅ 可行 | 付费功能（如高级报告、深度核对、历史导出）可保持闭源分发。Pro 功能的实现代码可放在私有模块 |
| 免费 + 订阅制 | ✅ 可行 | 需服务端能力。服务端代码天然不在客户端仓库中 |
| 免费 + 广告 | ⚠️ 有代价 | 与当前「无广告 SDK」的隐私定位直接冲突。若引入需重新评估 R4 全部合规材料（隐私政策、Data Safety、审核备注、商店文案） |

**关键点**：Android 应用可以用「同一代码库 + 私有模块」的方式构建，闭源部分不需要从公开发布的仓库里排除出去。GitHub 支持私有子模块或独立私有仓库承载 Pro 模块。

## 5. 若未来需要更强的保护

按性价比排序，供将来参考：

| 手段 | 成本 | 效果 | 建议时机 |
|---|---|---|---|
| 开启 Release 混淆（R8） | 低 | 中。提高反编译后的可读成本 | V0.3 发布前 |
| 商标注册 | 中 | 强。保护品牌而非代码 | 确定商业化方向后 |
| 核心逻辑下沉到服务端 | 高 | **强**。这是唯一真正无法反编译的保护 | 确定订阅制方向后 |
| Pro 功能拆到私有仓库 | 中 | 中。防止 Pro 实现被直接复制 | 确定 IAP 方向后 |
| 仓库转私有 | 低 | **弱**。APK 仍可反编译；且免费账号无法用 Pages 托管隐私政策 | 不推荐单独做 |

## 6. 执行时的注意事项

- **禁止**在仓库任何位置添加 OSI 批准的开源许可证（MIT / Apache-2.0 / GPL / 等），包括在子目录或单个源文件头部加 SPDX 标识。这会把整个项目变为开源。
- 若引入任何第三方库，必须核对其许可证是否允许商业闭源分发。Copyleft 类（GPL / AGPL / LGPL / MPL）需特别评估。
- 提交前运行密钥审计：`git ls-files | grep -iE "\.(jks|keystore|p12|pfx|key|pem)$|key\.properties"` 应无输出。
- 隐私政策公开 URL 由仓库 `gh-pages` 分支托管，内容从 `docs/release/v0.2/PRIVACY-POLICY.md` 生成 —— **该分支必须保持可公开访问**。
