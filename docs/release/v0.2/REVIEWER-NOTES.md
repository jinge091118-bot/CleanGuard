## 1. 应用概述（给审核人员的第一段）

CleanGuard 是一款本地存储占用分析工具。它扫描系统媒体索引，向用户展示空间分布与可查看的候选项（如大文件、旧文件、内容完全相同的重复文件），并允许用户逐项确认后将被选中的项目移入 Android 系统回收站。

**应用不具备网络能力**，所有分析在设备本机完成。

---

## 2. 权限使用说明

### 2.1 申请的权限

| 权限 | 用途 | 申请时机 |
|---|---|---|
| `READ_EXTERNAL_STORAGE`（maxSdk 32） | 读取媒体索引 | 用户点击授权按钮后 |
| `READ_MEDIA_IMAGES` | 同上 | 用户点击授权按钮后 |
| `READ_MEDIA_VIDEO` | 同上 | 用户点击授权按钮后 |
| `READ_MEDIA_AUDIO` | 统计音频占用 | 用户点击授权按钮后 |
| `READ_MEDIA_VISUAL_USER_SELECTED` | 识别部分授权范围 | Android 14+ 随媒体权限一并请求 |
| `PACKAGE_USAGE_STATS` | 读取各应用汇总占用 | 引导用户前往系统设置手动开启 |

**应用启动时不请求任何权限。** 所有媒体权限都需要用户主动点击「选择媒体访问范围」或「在系统中调整」后才触发系统弹窗。

### 2.2 关于使用情况访问（`PACKAGE_USAGE_STATS`）

这是本应用唯一属于 Play 敏感权限政策的权限，我们理解它需要单独申请与声明。

**使用理由**：CleanGuard 的「空间洞察」功能需要向用户展示各应用的汇总存储占用，帮助用户判断空间被哪些应用占用。Android 系统仅在用户于系统设置中手动授予「使用情况访问」后才向应用提供此数据。CleanGuard 不会尝试绕过该限制，不会在应用启动时请求，且仅读取汇总字节数（应用占用、数据占用、缓存占用），不读取任何应用内部文件，也不会清理其他应用的缓存。所有数值仅在应用内展示，不离开设备。

**已做限制**：
- 清单中以 `tools:ignore="ProtectedPermissions"` 显式标注该权限的受限性质
- 未申请 `QUERY_ALL_PACKAGES`，`<queries>` 仅声明 MAIN/LAUNCHER 意图
- 应用不清理其他应用缓存（界面已明确声明）

### 2.3 关于照片 / 视频权限

我们评估过使用系统 Photo Picker 的方案，但 CleanGuard 的核心功能需要**全量媒体库的只读视图**而非一次性选择集合：

- 需要持续展示各媒体类型的占用分布，而不是只统计用户单次挑选的项目
- 需要依赖 MediaStore Generation 感知库中变化并做增量更新
- 需要统计设备整体已用 / 可用空间与分类占比

因此在 Android 14+ 上我们完整支持并尊重「仅选择部分照片」，界面明确标注统计仅基于授权范围；在更早系统上请求传统只读媒体权限。

**应用不申请任何媒体写入或管理权限**：无 `WRITE_EXTERNAL_STORAGE`、无 `MANAGE_MEDIA`、无 `MANAGE_EXTERNAL_STORAGE`。

### 2.4 审核人员的自查路径

如需验证权限行为，建议按以下顺序操作（每一步都不需要网络）：

1. 安装并打开应用 → **不会出现任何权限弹窗**，首页正常显示
2. 点击「选择媒体访问范围」→ 此时才出现系统媒体权限弹窗
3. **拒绝**全部权限 → 应用不崩溃，扫描页提示「需要扫描范围授权」，其余页面可正常浏览
4. 授权后返回首页，点击「开始安全体检」→ 扫描完成并展示分类占用
5. 进入「设置与隐私」→ 隐私说明区可直接看到数据处理范围的文字说明

## 3. 核心功能与权限的对应

CleanGuard 的核心功能是存储占用分析与用户确认的清理。媒体读取权限直接服务于该功能：

- 统计照片 / 视频 / 音频各自占用
- 识别大文件、旧文件、录屏、截图等可查看项
- 计算并列出内容完全相同的重复文件
- 让你逐项选择后移入系统回收站

**没有媒体读取权限，核心功能无法实现。** 这是一个以「本机看清空间、只处理你确认的内容」为定位的工具。

## 4. 数据处理说明

### 4.1 应用不传输数据

- 未声明 `INTERNET` 权限
- 代码中无任何网络请求实现
- 依赖库全部为 AndroidX / Kotlin 官方库，无第三方 SDK
- 无分析、广告、崩溃上报 SDK
- 无后台任务、无开机自启、无云同步

### 4.2 读取的内容

| 场景 | 读取内容 | 是否离开设备 |
|---|---|---|
| 常规扫描 | MediaStore 索引的文件名、类型、大小、修改时间、相对目录 | 否 |
| 重复文件核对（仅在用户进入该页时） | 文件字节流，流式计算 SHA-256，不保存副本 | 否 |
| APK 洞察（仅在用户进入该页时） | 复制到应用私有临时目录并解析包名与版本，用后即删 | 否 |
| 应用占用（仅在用户进入该页时） | 系统提供的可启动应用汇总字节数 | 否 |
| 下载目录 | 用户通过系统选择器授权的目录，只读遍历元数据 | 否 |

**不读取**：照片或视频画面、EXIF、拍摄位置、缩略图、聊天内容、通讯录、通话记录、剪贴板、其他应用私有目录。

### 4.3 分享与预览

当用户主动点击「分享」或「预览」时，应用通过系统 Intent 把该文件的**只读 URI** 授权给用户在系统选择器中选定的应用。这完全由用户显式触发，接收方由系统选择器决定。除此之外无任何数据外流路径。

## 5. 删除行为的准确说明

请审核人员注意本应用**没有永久删除能力**：

- 唯一的删除路径是 `MediaStore.createTrashRequest`，即 Android 系统回收站
- 代码中**不存在** `createDeleteRequest`（永久删除）调用
- 每次处理都经过应用内确认 + Android 系统确认界面双重确认
- 系统确认被取消时不发生删除，也不会显示虚假的「已释放空间」
- 风险等级为 DANGER / UNKNOWN 的条目在引擎层被禁止任何删除动作；REVIEW 条目默认不选中
- 不提供全局一键清理
- SAF 授权的下载目录文件不可被本应用删除：安全规则在数据层排除非 MediaStore 来源，且该授权只申请只读权限

## 8. 已知限制（供审核参考，不影响合规性）

- 不识别相似图片或近似视频，仅确认内容完全相同的重复文件
- 移入系统回收站通常不会立即释放物理空间
- 恢复中心只覆盖本应用移入系统回收站的项目
- 应用占用统计仅覆盖有桌面图标的应用
- Android 10 不支持系统回收站，清理功能需要 Android 11 及以上
