# CleanGuard V0.2 R5 Google Play 内部测试方案

**状态**：草案，待项目所有者批准后执行
**前置条件**：R4 全部完成并获批（隐私政策公开 URL、Data Safety、权限声明、审核备注）
**目标**：在 Google Play 内部测试轨道验证真实设备上的安装、启动、权限与基础功能，并收集首轮问题

---

## 1. 轨道配置

| 项目 | 建议设置 | 说明 |
|---|---|---|
| 轨道 | Internal testing | Google 推荐内部测试用 12 个测试者或最多 100 名 |
| 测试者数量 | 20 – 30 人 | 覆盖多品牌多价位 |
| 发布方式 | 手动发布 | 每次上传新版本后手动推进，避免自动把未验证版本推给测试者 |
| 分阶段百分比 | 内部测试不需要 | 内部测试对测试者全量可见 |

---

## 2. 测试者招募要求

内部测试的价值在于覆盖真实硬件多样性。请按以下配额招募：

| 维度 | 目标覆盖 | 优先级 |
|---|---|---|
| 品牌 | 小米/红米、华为、OPPO/vivo、荣耀、三星 | 覆盖 `DEVICE-MATRIX.md` 中标记 P0/P1 的全部家族 |
| Android 版本 | 10、11、12、13、14、15、16 各至少 1 台 | R2 要求覆盖 Android 10 – 16 |
| 存储容量 | ≥ 64 GB | 需容纳真实媒体 |
| 特殊系统 | HyperOS、ColorOS、MagicOS、OriginOS、One UI 各至少 1 台 | 这些 ROM 对权限弹窗与后台行为有定制 |

**若无法覆盖某个家族**，须在 `DEVICE-MATRIX.md` 中保持该行未通过，不得因内部测试有其他机型通过就改写。

---

## 3. 分阶段推进

### 阶段 1：冒烟（3 天，5 – 8 名测试者）

**目标**：确认应用能装、能启、能授权、能扫描。

| 检查项 | 通过标准 |
|---|---|
| 安装 | 从 Play 链接安装成功，无签名冲突 |
| 首次启动 | 正常进入首页，**无权限弹窗自动弹出** |
| 权限申请 | 点击「选择媒体访问范围」后才出现系统弹窗 |
| 拒绝权限 | 不崩溃，首页可浏览，扫描页给出授权提示 |
| 授权后扫描 | 扫描完成，展示分类占用 |
| 清理流程 | 能进入系统回收站确认界面；取消后无虚假空间提示 |
| 崩溃 | 无 ANR、无崩溃 |

**任何 P0 问题在此阶段出现即暂停发布。**

### 阶段 2：广度（7 – 14 天，全部测试者）

**目标**：覆盖各 ROM 的差异行为。

| 检查项 | 通过标准 |
|---|---|
| 权限弹窗在各 ROM 上正常显示 | 部分 ROM 会要求「后台弹出界面」权限，需在测试说明中告知 |
| 系统回收站确认界面在各 ROM 上正常弹出 | 若被 ROM 拦截，记录拦截方式 |
| 扫描结果与设备实际媒体一致 | 数量级正确，不出现大量 0 字节或异常条目 |
| 应用占用页 | 数值与系统设置中的存储统计大致一致 |
| 重复文件页 | 能正确识别内容相同的文件；默认全部未选中 |
| 空间趋势 | 多次扫描后趋势图正常显示 |
| 后台稳定性 | 切后台再返回无异常 |
| 耗电 | 无异常唤醒（`adb shell dumpsys batterystats`） |

### 阶段 3：收敛（3 – 5 天）

- 分类处理收集到的问题
- P0/P1 清零后推进到 R6

## 5. 测试者说明（发给测试者）

以下内容可直接复制发送给测试者。

---

### CleanGuard 内部测试说明

**这是什么**：一款在手机本机运行的存储占用分析工具。它帮你看清空间被什么占用了，再由你决定是否处理。

**请注意的三点**

1. **它不联网。** 应用没有网络权限，不上传任何东西。可以开飞行模式使用。
2. **它不永久删除文件。** 被选中的项目会移入 Android 系统回收站，保留多久由系统决定。想找回可以在应用内的「恢复中心」发起恢复。
3. **它不读取你的照片内容。** 常规扫描只读文件名、类型、大小、时间和目录。只有你主动点进「重复文件」页面时，才会流式计算哈希来确认内容是否完全相同。

**怎么用**

1. 打开后先看首页的空间概览
2. 点「选择媒体访问范围」，在系统弹窗里选择允许的范围（Android 14+ 可以只选部分照片）
3. 点「开始安全体检」等扫描完成
4. 在结果页查看分类占用和建议
5. 想处理时逐项确认，走系统确认界面移入回收站

**遇到问题请反馈**

- 机型与系统版本（如：小米 14 / Android 14 / HyperOS）
- 你做了什么操作
- 期望结果是什么，实际发生了什么
- 如果有报错，请附截图

**请不要提供**：你的私人照片、视频、完整系统日志或私人文件路径。描述问题即可。

## 6. 问题收集

所有反馈记入 `BETA-FEEDBACK.md`，按 `BUG-TRACKER.md` 的严重级别定义定级：

| 级别 | 定义 |
|---|---|
| P0 | 数据丢失、错误删除、崩溃循环、DANGER/UNKNOWN 被删除、权限被绕过、数据库损坏 |
| P1 | 扫描失败、回收站/恢复失败、严重 ANR、主界面不可用 |
| P2 | 可复现的 OEM 兼容问题、明显性能回退、严重 UI 错误 |
| P3 | 轻微 UI、文案或非核心体验问题 |
