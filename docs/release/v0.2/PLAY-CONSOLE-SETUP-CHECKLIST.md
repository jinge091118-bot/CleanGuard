## 0. 先做一个决定：账号类型

这是**唯一会影响时间线**的选择，建议在注册前就想清楚。

### 两者对比

| 维度 | 个人账号 | 组织账号 |
|---|---|---|
| 身份材料 | 身份证件 + 地址 | 公司营业执照 + D-U-N-S 编号 + 联系人 |
| 准备周期 | 几小时到几天 | 几天到几周（D-U-N-S 审核占大头） |
| 注册费 | 一次性 25 美元 | 一次性 25 美元 |
| **12 人 × 14 天封闭测试** | **必须** | **豁免** |
| 正式版权限 | 需测试达标后申请 | 可直接申请 |
| 商店页联系人 | 你本人 | 公司公开信息 |
| 收款 | 需税务表单（个人） | 需公司税务信息 |
| 账号转让 | 麻烦 | 相对可行 |

### 我的建议

**如果 CleanGuard 只是试水、验证市场反应** → 个人账号。零额外准备，先跑起来。

**如果你已经打算长期做（尤其是你提到过收费会员订阅）** → 组织账号。理由：

1. **省掉 14 天窗口** —— 长期看这是永久性的一次性节省
2. 账号更稳定。个人账号转让麻烦，如果未来要融资、合伙或交给团队，组织账号的基础更干净
3. 商店页显示公司信息，对「付费订阅」这种需要信任的商业模式更有说服力

**代价**：D-U-N-S 编号申请免费但要几天到几周。可以在等待期先把应用准备到上传就绪（现在已经是了）。

### D-U-N-S 编号申请要点

| 项目 | 说明 |
|---|---|
| 入口 | `https://developer.apple.com/duns/` 不对 —— 正确入口是 Play Console 内的「设置 → 开发者账号 → 管理开发者账号 → 组织开发者账号」，会引导你申请 |
| 需要的公司材料 | 营业执照 / 法人身份证明 / 公司地址证明 / 公司电话 |
| 常见卡点 | 公司名称必须与营业执照**完全一致**（含标点、后缀）。名称不一致是驳回的首要原因 |
| 周期 | 通常 3–10 个工作日 |

> **实操建议**：如果决定走组织账号，**立刻去申请 D-U-N-S**。这是整条路径上唯一一个「纯等待、不需要你做任何事」的环节，越早启动越好。

### 如果你现在还没有开发者账号

**当前状态下无法做任何 Play Console 操作** —— 内容分级、Data Safety、敏感权限申请、商店信息全部要在账号创建后才能填。

所以第一步是注册。注册时的选择就是上面那个决定。

## 1. 注册与首次设置清单

### 1.1 注册

| 项目 | 说明 |
|---|---|
| 入口 | `https://play.google.com/console` |
| 费用 | 一次性 25 美元 |
| 账号类型 | 按 §0 决定 |

### 1.2 身份验证

| 项目 | 说明 |
|---|---|
| 材料 | 政府签发的身份证件（个人）或公司登记文件（组织） |
| 常见卡点 | 姓名必须与证件**完全一致**，包括拼音/英文写法。中间名、空格、大小写不一致都会被驳回 |
| 提示 | 地址要填真实可验证的，Google 可能寄验证信或要求上传证明 |

### 1.3 付款方式

| 项目 | 说明 |
|---|---|
| 可用方式 | 信用卡（Visa / Mastercard / American Express）、Google Play 余额、部分地区的本地支付方式 |
| 注意 | **必须用与开发者账号国家/地区一致的卡**。跨国卡会被拒 |
| 验证 | 通常会扣一笔很小的金额（1–3 美元）验证 |

### 1.4 设备验证（个人账号必做）

| 项目 | 说明 |
|---|---|
| 要求 | 在 **Play Console 移动端 App** 上完成，使用**实体机、非 root、Android 10 或以上**的手机 |
| 为什么 | Google 要确认你是真人操作，且设备环境未被篡改 |
| 常见卡点 | 设备上有 root、已解锁 bootloader、或安装了 Xposed/Frida 等框架 → 会被拒 |

> **这一条和 R2/R3 的真机需求是同一批设备**。如果本来就打算买一台中端安卓真机做性能采集，**用它完成设备验证**，一次投入两处使用。

### 1.5 创建应用条目

| 字段 | 填写 |
|---|---|
| 应用名称 | `CleanGuard` |
| 默认语言 | 简体中文（可加英语） |
| 应用或游戏 | **应用** |
| 免费或付费 | **免费**（当前无 IAP） |
| 声明 | 勾选两项政策声明（内容分级 + 目标受众），后续补全 |

**⚠️ 注意**：应用名称一旦创建**几乎不能改**。确认后再提交。

### 1.6 上传第一个版本

| 项目 | 值 |
|---|---|
| 产物 | `app/build/outputs/bundle/release/app-release.aab` |
| 版本号 | 2（**前提：从未上传过**） |
| 版本名 | 0.2.0 |
| 轨道 | 内部测试 |

**上传前请先跑一遍校验**：

```bash
python3 tools/release/verify-aab.py
```

该脚本检查签名密钥类型、版本号、SDK 版本、权限清单与隐私政策的一致性、调试标记、产物完整性。2026-10-26 的实测结果为全部通过。

## 2. 时间线速查

假设今天开始准备：

| 阶段 | 何时 |
|---|---|
| 注册 + 身份验证 + 付款 | 第 1–2 天 |
| 设备验证（个人账号） | 第 2–3 天 |
| 创建应用条目 + 上传 AAB 到内部测试 | 第 3 天 |
| 填敏感权限申请 / Data Safety / 内容分级 / 目标受众 | 第 3–4 天 |
| 商店信息与素材（素材需真机） | 第 4–7 天 |
| 内部测试轨道运行 | 第 4–18 天 |
| **封闭测试 14 天窗口** | 第 19–33 天 |
| 申请正式版权限 + 审核 | 第 34–40 天 |
| 正式版审核 + 上架 | 第 41–45 天 |

**这是个人账号 + 有真机的完整路径，约 6 周。**

组织账号可省去第 19–33 天，约 4 周。
