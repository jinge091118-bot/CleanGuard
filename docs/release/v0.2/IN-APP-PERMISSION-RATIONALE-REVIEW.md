## 审查方法

逐条比对界面文案与代码实际行为。判定标准：

- **一致**：文案所述与代码行为完全吻合
- **不完整**：文案本身没错，但漏掉了用户应知的行为
- **过度表述**：文案字面正确但易被理解为更强的承诺
- **错误**：与代码行为不符

---

## 权限中心文案审查

权限中心的结构是：每项权限一张卡片，包含**状态**（已授权 / 部分授权 / 未授权）、**用途**、**未授权时的影响**，以及「在系统中调整」入口。

| 权限项 | 文案 | 判定 | 依据 |
|---|---|---|---|
| 照片 | 用途：分析授权范围内的媒体占用、大文件和重复候选。<br>未授权时仍可使用应用，但无法完整分析照片和视频空间。 | 一致 | 照片扫描走 MediaStore；未授权时 `ScanningViewModel.kt:69-79` 走降级路径并给出提示 |
| 视频 | 同上 | 一致 | 同上 |
| 音频 | 用途：分析音频媒体的占用情况。<br>未授权时仍可使用应用，但音频空间不会被统计。 | 一致 | 音频单独归类，缺失时仅音频统计为空 |
| Downloads SAF | 用途：只分析你通过系统选择器授权的下载目录。<br>未授权时不分析 Downloads 中的文件和 APK。 | 一致 | `SafDownloadAccessRepository.kt:58-61` 只接受系统选择器返回的授权 |
| 使用情况访问 | 用途：读取系统提供的应用占用统计。<br>未授权时不显示应用占用增长，其他扫描功能仍可使用。 | 一致 | `AndroidAppStorageRepository.kt:31-42` 用 `AppOpsManager` 检测；`LoadAppStorageUseCase.kt:18-20` 走空数据分支 |

**整体评价**：权限中心的文案结构完整 —— 每项都说明了「用来做什么」和「不给会怎样」，这正是 Play 审核期望看到的用户教育形态。「权限不会阻止进入 CleanGuard。你可以只授予需要分析的范围。」（`permission_center_intro`）这一句同时安抚了拒绝场景并强调了最小授权原则。

**无需修改。**

## 设置页隐私说明

### 修订前

```
所有扫描均在本机完成。
CleanGuard V0.2 不上传文件。
CleanGuard V0.2 不读取聊天内容。
CleanGuard V0.2 不访问其他 App 私有目录。
```

### 审查发现

| 文案 | 判定 | 说明 |
|---|---|---|
| 所有扫描均在本机完成。 | 一致 | 无网络能力，全部本地查询 |
| CleanGuard V0.2 不上传文件。 | **不完整** | 字面成立（无 `INTERNET` 权限），但未覆盖用户主动使用「分享」/「预览」时文件 URI 通过系统 Intent 授权给第三方应用的行为。用户据此可能认为数据绝无可能离开设备 |
| CleanGuard V0.2 不读取聊天内容。 | 一致 | 无 `SmsManager`、无 `ContactsProvider`、无 `CallLog`、无剪贴板读取 |
| CleanGuard V0.2 不访问其他 App 私有目录。 | 一致 | 仅用 `StorageStatsManager` 取汇总字节数；未申请 `MANAGE_EXTERNAL_STORAGE`；`android/data/` 在安全规则中标为 DANGER |

### 修订后

```
所有扫描均在本机完成。
CleanGuard 不上传文件；除移入 Android 系统回收站与你主动使用系统分享/预览外，数据不会离开设备。
CleanGuard V0.2 不读取聊天内容。
CleanGuard V0.2 不访问其他 App 私有目录。
```

**已修改**：补充了分享/预览这一唯一的对外授权路径，避免用户基于不完整信息形成误判。

### 新增条目

同时新增两条，覆盖审计中发现的、原文案未提及的处理行为：

```
常规扫描只读取文件名、类型、大小、修改时间与目录，不读取媒体内容。
核对重复文件时会在本机流式计算 SHA-256，不保存文件副本。
```

**理由**：这两条是 CleanGuard 唯一两处读取文件内容或读取非显然字段的地方。用户若不阅读隐私政策，应当能在设置页内获知。原文案只说「本机完成」，没有说明「读了什么」。

## 首页文案

### 修订前

```
设备容量与扫描结果均在本机生成；当前只读取索引和你明确授权的目录，不会修改任何文件。
```

### 审查发现

**过度表述**。这句的上下文限定在「设备容量与扫描结果」这一段，本身没错，但「不会修改任何文件」是一个无限定范围的绝对否定 —— 而 CleanGuard **确实会修改文件**（将项目移入系统回收站）。放在首页这种高频位置，用户容易理解为「这个应用永远不会动我的文件」，与后续实际发生的移入回收站行为构成认知落差。

### 修订后

```
设备容量与扫描结果均在本机生成；本步骤只读取索引和你明确授权的目录，不会修改文件。
```

**已修改**：加入「本步骤」限定，把陈述范围明确收敛到扫描步骤本身。既消除了绝对否定，又保留了「扫描是只读的」这一准确且有价值的信息。
