**应用**：`com.cleanguard.app` / version code 2

## 1. 声明的权限

| 权限 | Manifest 声明 | 适用系统 |
|---|---|---|
| `READ_EXTERNAL_STORAGE` | `android:maxSdkVersion="32"` | Android 10 – 12 |
| `READ_MEDIA_IMAGES` | 默认 | Android 13+ |
| `READ_MEDIA_VIDEO` | 默认 | Android 13+ |
| `READ_MEDIA_AUDIO` | 默认 | Android 13+ |
| `READ_MEDIA_VISUAL_USER_SELECTED` | 默认 | Android 14+ |

**未声明**：`MANAGE_MEDIA`、`MANAGE_EXTERNAL_STORAGE`、`READ_MEDIA_AUDIO` 之外的任何媒体管理权限、`WRITE_EXTERNAL_STORAGE`。

---

## 2. 核心功能与权限的对应关系

CleanGuard 的核心功能是**设备存储占用分析与用户确认的清理**。该功能必须能够看到媒体库中有哪些文件、各自多大，才能完成：

- 统计照片 / 视频 / 音频分别占用了多少空间
- 识别大文件、旧文件、录屏、截图等可查看的候选项
- 计算并列出内容完全相同的重复文件
- 让你逐项选择后，将选中项目移入 Android 系统回收站

**没有媒体读取权限，上述功能均无法实现。** CleanGuard 是一款以「看懂空间、只处理你确认的内容」为定位的工具，媒体占用数据就是它的产品主体。

---

## 3. 为什么不能用系统 Photo Picker 替代

Google Play 鼓励应用优先使用系统 Photo Picker，以减少权限使用面。CleanGuard 经过评估后认为 Photo Picker **无法满足核心功能**，理由如下：

| 维度 | 系统 Photo Picker | CleanGuard 的需求 |
|---|---|---|
| 选择粒度 | 用户每次手动挑选具体项目 | 需要**全量**媒体库视图 |
| 交互成本 | 每次查看统计都要重新进入选择器 | 一次授权，持续查看空间分布 |
| 覆盖范围 | 依赖文档提供方实现，可能不完整 | 需要系统媒体库的完整索引 |
| 增量更新 | 无法感知库中变化 | 依赖 MediaStore Generation 做增量扫描 |
| 空间统计 | 只能统计被选中的项目 | 需要展示设备整体已用/可用空间与分类占比 |

**结论**：Photo Picker 适合「让用户选几张图做一次性处理」的场景；CleanGuard 的场景是「先看清空间分布，再决定处理什么」，需要的是库的只读视图而非选择器。CleanGuard 已在 Android 14+ 上支持并尊重「仅选择部分照片」，在 Android 14 以下则请求传统只读媒体权限。

## 4. 使用方式与用户控制

- **按需申请**：所有权限都在用户主动点击「选择媒体访问范围」或「在系统中调整」后才请求，应用启动时不请求任何权限。
- **部分授权支持**：Android 14+ 用户可选择仅授权部分照片和视频。CleanGuard 会检测 `READ_MEDIA_VISUAL_USER_SELECTED` 并在界面上明确标注「当前为部分媒体访问」「媒体容量统计基于当前授权范围」。
- **可随时撤销**：用户可在系统设置中随时撤销媒体权限。撤销后 CleanGuard 不再能读取对应媒体，界面会显示未授权状态，扫描相应部分会被跳过并给出说明。
- **拒绝后可用**：拒绝权限不会导致应用崩溃或无法使用。CleanGuard 会明确提示「未授权时仍可使用应用，但无法完整分析照片和视频空间」。
- **只读**：不申请任何媒体写入或删除权限。

## 5. 数据的具体用途

| 数据 | 用途 | 是否离开设备 |
|---|---|---|
| 文件名 | 展示候选项、判断是否为 APK / 截图 / 录屏 | 否 |
| 文件类型 | 按图片 / 视频 / 音频分类 | 否 |
| 文件大小 | 统计占用、识别大文件 | 否 |
| 修改时间 | 判断文件新旧、生成建议优先级 | 否 |
| 相对目录路径 | 识别 Downloads、录屏目录等 | 否 |
| 文件字节内容 | **仅在进入「重复文件」页时**流式计算 SHA-256，以确认内容完全相同 | 否 |

**不读取**：照片或视频的画面内容、EXIF、拍摄位置、缩略图。

**哈希计算的说明**（审核问询时使用）：

> CleanGuard 的「重复文件」功能需要确认候选文件内容是否**完全相同**。为此它在本机以 64 KiB 固定缓冲流式计算 SHA-256，不会把整个文件读入内存，不保存文件副本，不产生任何图像副本或缩略图。计算结果（哈希值）仅缓存在本机数据库中用于加速后续比对。该功能只在用户主动进入重复文件页面时触发。

## 6. 清理行为的准确描述

提交审核时必须避免以下**不准确**的表述：

| ❌ 不要这样写 | ✅ 准确表述 |
|---|---|
| 「删除不需要的文件以释放空间」 | 「将你选择的项目移入 Android 系统回收站；保留时长由系统决定，通常不会立即释放物理空间」 |
| 「一键清理」 | 「不提供全局一键清理；DANGER 与 UNKNOWN 条目无法进入处理流程，REVIEW 条目默认不选中」 |
| 「可恢复已删除的文件」 | 「恢复中心只显示并恢复由 CleanGuard 移入系统回收站的项目」 |
| 「智能识别相似照片」 | 「仅确认内容完全相同的重复文件，不提供相似图片判断」 |
| 「读取照片内容以分析」 | 「常规扫描只读取索引元数据；仅重复文件核对会流式读取字节计算哈希」 |

**关键事实**（审核时可直接引用）：

- 唯一的删除路径是 `MediaStore.createTrashRequest`，即 Android 系统回收站，代码中**不存在** `createDeleteRequest`（永久删除）调用。
- 每次处理都经过应用内确认 + Android 系统确认界面双重确认。
- SAF（下载目录）文件不可被 CleanGuard 删除：安全规则在数据层排除非 MediaStore 源，且 SAF 授权只申请只读权限。
- 永久删除动作在规则中存在但仅匹配应用自身缓存目录，生产扫描路径永不产生该类来源，因此实际不可达。

## 7. 审核问询准备

### Q：能否改用 Photo Picker 以减少权限使用面？

> 已在评估中。CleanGuard 的核心功能是展示**全量**媒体占用分布并支持增量更新，Photo Picker 只能提供用户单次挑选的项目集合，无法支撑空间统计与增量扫描。CleanGuard 已在 Android 14+ 上完整支持「仅选择部分照片」并在界面标注授权范围，在更早系统上请求传统只读权限以便完成核心功能。

### Q：为什么需要 `READ_MEDIA_AUDIO`？

> 应用对照片、视频、音频做统一的分类占用统计。音频与照片视频属于同一媒体库索引与同一套空间分析模型，去掉音频会让「空间分类」出现无法解释的空缺，也无法在 Downloads 之外给出完整的媒体占用构成。

### Q：会读取用户照片的内容吗？是否有上传？

> 应用不声明 `INTERNET` 权限，没有网络能力，不存在任何上传路径。常规扫描只读取索引元数据。唯一读取文件字节的功能是重复文件核对，在本机流式计算 SHA-256，不保存副本、不产生图像内容。

### Q：`PACKAGE_USAGE_STATS` 为什么需要？

> 该权限用于「空间洞察」页展示各应用的汇总占用。Android 仅在用户于系统设置中手动开启后提供此数据，应用不会尝试绕过限制，仅读取汇总字节数，不读取应用内部文件，也不清理其他应用缓存。详见 `DATA-SAFETY.md` 中的受限权限使用理由。
