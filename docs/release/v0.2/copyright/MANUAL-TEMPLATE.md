# CleanGuard 软件著作权登记 —— 软件说明书写作模板

**用途**：中国版权保护中心软著申请的第二份必交材料
**状态**：结构与截图位已就绪，**文字部分需人工撰写**
**重要**：2026 年 3 月起软著审查从形式审查转为实质审查，且**明确禁止 AI 生成材料**，须提交承诺书。本模板提供结构与要点提示，**正文需由你本人撰写**

---

## 0. 提交规范速查

| 项目 | 要求 |
|---|---|
| 页数 | 建议 **15 页以上**，最低不少于 10 页 |
| 每页文字 | 不少于 30 行 |
| 必备内容 | 软件功能介绍、运行环境、操作流程、**功能截图**、模块说明 |
| 截图要求 | 必须插入真实运行界面截图；截图名称、版本号须与申报信息一致 |
| 格式 | PDF，页面与申请表一致 |
| 与申请表一致性 | 软件名称、版本号、著作权人 **一字不差** |

**最常见的驳回原因**：说明文档敷衍 —— 无功能截图、内容与软件不符、纯文字无实操说明。

## 1. 文档整体结构

以下每章都标注了**篇幅建议**、**必须包含的内容**和**截图位**。

---

### 第 1 章 软件概述（约 1–1.5 页）

**必须包含**：

- 软件全称（与申请表、源码页眉严格一致）
- 版本号
- 开发完成日期、首次发表日期
- 开发方式（独立开发）
- 著作权人
- 一段 300–500 字的总体说明：软件解决什么问题、面向什么用户、核心特点是什么

**写作提示**：这一段是审核员读到的第一段文字，要说清楚「这是一个本地存储占用分析工具，不联网、不上传数据、清理需逐项确认」。

---

### 第 2 章 运行环境（约 1 页）

**必须包含**：

| 项目 | 内容 |
|---|---|
| 硬件要求 | 设备类型、处理器架构、内存、存储空间 |
| 软件要求 | 操作系统版本范围 |
| 开发语言 | Kotlin |
| 开发工具 | Android Studio、Android SDK、Gradle、JDK 17 |
| 关键依赖 | AndroidX（Compose / Room / Navigation / DataStore）、kotlinx-coroutines |
| 网络要求 | **明确写「不需要网络连接」** |

> ⚠️ 「网络要求」这一项对本软件特别重要 —— 它和第 5 章的隐私说明相互印证。

---

### 第 3 章 功能模块说明（约 3–4 页）

按模块逐一说明。每个模块写：**功能描述 → 操作步骤 → 截图**。

#### 3.1 权限管理与隐私说明模块

**要点**：

- 全部权限均在用户主动点击后请求，应用启动不请求任何权限
- 各项权限的用途与未授权时的影响
- 数据仅在设备本地处理，不上传
- 不联网、无第三方 SDK

**截图位**：
- 权限中心完整页面（含每项权限的用途与影响说明）
- 部分媒体访问状态页面

#### 3.2 存储扫描与分类模块

**要点**：

- 扫描 MediaStore 索引的字段范围（文件名、类型、大小、修改时间、相对目录）
- 不读取媒体内容
- Android 11+ 基于 Generation 的增量扫描机制
- 分类维度（大文件、旧文件、录屏、截图、旧 APK、重复项）
- 空间趋势与历史记录

**截图位**：
- 首页容量总览
- 扫描结果页（含分类与建议列表）
- 空间趋势页

#### 3.3 安全规则与风险评估模块

**要点**：

- 独立的规则引擎输出风险等级（DANGER / REVIEW / SAFE / UNKNOWN）
- 建议优先级与风险等级相互独立
- DANGER 与 UNKNOWN 不提供任何删除动作
- REVIEW 默认不选中
- 规则的匹配维度（路径、扩展名、MIME、来源）

**截图位**：
- 结果页中同时出现 DANGER 与 REVIEW 条目的画面（体现两套体系并存）
- 规则说明或风险标识的特写

#### 3.4 重复文件确认模块

**要点**：

- 文件大小 → 快速哈希 → 完整 SHA-256 的三级比对
- 流式计算，不整体载入内存，不保存文件副本
- 缓存复用机制
- 默认不选中任何文件，由用户逐项决定

**截图位**：
- 重复文件组列表（**复选框全部未选中**）
- 单个重复组的详情页

#### 3.5 清理执行与恢复模块

**要点**：

- 走 Android 系统回收站，不永久删除
- 应用内确认 + 系统确认双重机制
- 清理历史记录（时间、数量、空间、关联 URI）
- 恢复中心只显示本应用移入回收站的项目

**截图位**：
- 清理前确认页（含风险等级与允许动作）
- 系统回收站确认界面
- 清理历史列表
- 恢复中心页面

#### 3.6 空间洞察与 APK 分析模块

**要点**：

- 使用情况访问权限的引导流程
- 仅统计有桌面图标的应用，仅取汇总字节数
- 不读取应用内部文件，不清理其他应用缓存
- APK 元数据解析（包名、版本、标签）与包可见性限制的处理

**截图位**：
- 应用占用列表页
- APK 洞察页

---

### 第 4 章 操作流程（约 2–3 页）

**用连续的文字 + 截图说明一次完整的使用流程**。建议按这个顺序：

| 步 | 操作 | 截图 |
|---|---|---|
| 1 | 打开应用，首页显示设备容量与授权状态 | 首页初始态 |
| 2 | 点击「选择媒体访问范围」，在系统弹窗中授权 | 系统权限弹窗 |
| 3 | 点击「开始安全体检」，扫描完成 | 扫描进行中 / 完成 |
| 4 | 查看结果页的分类占用与建议列表 | 结果页 |
| 5 | 进入重复文件页，逐项确认 | 重复文件页 |
| 6 | 选中要处理的项，进入清理详情 | 清理详情页 |
| 7 | 在系统确认界面确认 | 系统确认界面 |
| 8 | 在清理历史或恢复中心查看结果 | 历史页 |

> **截图必须是真实运行界面**。这也是为什么 `STORE-ASSET-CAPTURE-SCRIPT.md` 产出的截图可以直接复用 —— 但注意：**商店截图和软著说明书截图是两套用途**，软著要求「操作流程」完整连贯，商店要求「卖点」突出。

---

### 第 5 章 隐私与数据安全说明（约 1–1.5 页）

**要点**（这一章在实质审查中权重最高）：

- 无网络访问能力，未声明 `INTERNET` 权限
- 不含任何第三方 SDK、统计、广告、崩溃上报
- 扫描仅读取索引元数据，不读取媒体内容
- 重复文件核对在本机流式计算哈希，不保存副本
- 本地数据库不参与云备份与设备迁移
- 唯一的对外数据路径：移入系统回收站，以及用户主动触发的系统分享/预览
- 权限最小化：启动不请求，拒绝不影响使用

---

### 第 6 章 版本信息与声明（约 0.5 页）

**必须包含**：

- 本版本的功能范围
- 已知限制（诚实列出，例如「不识别相似图片」「移入回收站不立即释放物理空间」）
- 著作权声明
- 联系方式（支持邮箱 `jinge091118@gmail.com`）

> ⚠️ 诚实列出限制反而是加分项 —— 实质审查会核对文档描述与实际行为是否一致，夸大功能是驳回高发原因。

## 3. 一致性检查清单（提交前逐项确认）

- [ ] 软件名称：申请表 = 源码页眉 = 说明书页眉 = 上架应用名，**一字不差**
- [ ] 版本号：四处统一（如 `V1.0` / `0.2.0` / `1.0.0` 需事先选定一种格式）
- [ ] 著作权人：申请表 = 主体证明材料，**与最终上架主体一致**
- [ ] 开发完成日期 **早于** 首次发表日期
- [ ] 源代码文档：60 页、每页 ≥50 行有效代码、页眉含软件名与版本号、无遮挡无乱码无水印
- [ ] 说明书：≥15 页、每页 ≥30 行文字、含真实界面截图
- [ ] 截图上的版本号与申报信息一致
- [ ] 说明书描述的功能与实际应用**完全对应**（实质审查会核对）
- [ ] 申请表已签章（个人手写签名 / 企业盖章）
- [ ] **AI 使用情况如实声明**（2026 年新规）

## 5. 官方办理入口与时限

| 项目 | 内容 |
|---|---|
| 唯一官方入口 | <https://register.ccopyright.com.cn/registration.html#/registerSoft> |
| 材料提交 | 全部线上，无需邮寄纸质材料 |
| 受理核查 | 5–7 个工作日（材料不全会下发补正通知，30 日内补正，逾期视为撤回） |
| 正式审查 | 受理后 60 个自然日 |
| 普通通道 | 约 1.5–2 个月 |
| 加急通道 | 3 / 5 / 10 / 20 个工作日，1000–5000 元 |
| 证书形式 | 优先电子证书，与纸质同等法律效力 |
| 费用 | 官方自办 **0 元** |
| 年审 | **不需要**，一次登记长期有效 |

**⚠️ 官方从不指定任何第三方中介，也从不收取费用。** 自行通过官方渠道办理。
