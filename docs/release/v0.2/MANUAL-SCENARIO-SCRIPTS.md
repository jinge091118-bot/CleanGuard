# CleanGuard V0.2 手测场景执行脚本

**状态**：待真机执行
**用途**：R2 设备矩阵中尚未完成的手动场景，可在任意品牌真机（Android 10 – 16）上执行
**依据**：`BUG-TRACKER.md` 的 `R2-COV-01` 与 `OEM-DEVICE-VALIDATION-REPORT.md` 的剩余场景清单

---

## 通用前置条件

### 环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 设备 | 物理真机 | **必须是真实硬件**。执行前按下方「设备身份核实」确认 |
| 存储 | ≥ 5 GB 可用 | 需容纳测试媒体 |
| 电量 | ≥ 50% | 低于此值需先充电 |
| 温度 | 无节流 | `dumpsys thermalservice` 的 `Thermal Status` 应为 0 |
| 网络 | 可关闭 | 应用不需要网络；可开飞行模式验证 |
| 系统更新 | 无进行中 | 避免中途重启 |

### 设备身份核实（每次执行前必做）

R3 采集时曾遇到一台自报 `Pixel 5` 但实为虚拟化 Android 12 平台的设备。执行任何真机验收前必须排除这种情况：

```bash
adb shell getprop ro.product.model
adb shell getprop ro.kernel.qemu          # 应为空
adb shell uname -a                        # 主机名不应为 localhost
adb shell cat /proc/cpuinfo | grep Hardware   # 物理机应有 Hardware 行
adb shell dumpsys sensorservice | grep -i "Sensor |" | head -5   # 厂商应为设备真实厂商
adb shell dumpsys thermalservice | grep "Thermal Status"
```

**判定**：出现以下任一情况即判定为非物理设备，该设备的结果**不得**计入 R2/R3：
- `ro.kernel.qemu` 非空
- `uname -a` 主机名为 `localhost` 或其他通用名
- `/proc/cpuinfo` 无 `Hardware` 行
- 传感器厂商与 `ro.product.manufacturer` 明显不符
- 缺少陀螺仪 / 重力 / 旋转向量传感器（物理机通常都有）

### 测试数据

- 只使用**应用自建的合成数据**，不得使用测试者自己的私人照片、视频或文件
- 合成数据统一放在设备的 `Pictures/CleanGuardManual/` 目录，测试结束后删除该目录
- 不得在设备上安装无关应用或开启无关的无障碍服务

### 记录方式

每条场景记录以下字段（可复制本文件的表格）：

| 字段 | 内容 |
|---|---|
| 场景编号 | 如 `M-01` |
| 设备 / ROM | 品牌型号 / 系统版本 |
| Android / API | 如 Android 13 / API 33 |
| 执行日期 | |
| 结果 | 通过 / 失败 / 阻塞 |
| 证据 | 截图路径或 logcat 片段 |
| 缺陷编号 | 若失败，填 BUG-TRACKER 里的 ID |

## 场景 M-01：部分照片授权（Android 14+）

**前置**：Android 14 或更高版本。已安装的应用需为 V0.2 正式版。

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 打开 CleanGuard，进入首页 | 首页正常显示，**不弹出任何权限请求** |
| 2 | 点击「选择媒体访问范围」 | 出现系统权限弹窗，其中包含「选择照片和视频」/「仅选择部分照片」等选项（具体文案依 ROM 而异） |
| 3 | 选择「仅选择部分照片」，选中 2 – 3 张 | 返回应用 |
| 4 | 观察权限中心状态 | 照片与视频显示「部分授权」；出现「当前为部分媒体访问」提示卡 |
| 5 | 执行一次「安全体检」 | 扫描完成；统计范围仅包含选中的项目 |
| 6 | 观察空间分类中的照片/视频容量 | 数值显著小于未做部分授权时的完整统计（与步骤 7 对比） |
| 7 | 回到系统设置，改为「全选」或完全授权 | — |
| 8 | 重新执行一次扫描 | 照片/视频容量上升；权限中心状态变为「已授权」；「部分媒体访问」提示卡消失 |

**通过标准**：步骤 4、5、6、8 的状态与数值变化全部符合；部分授权下的统计不得包含未授权项目。

**OEM 差异记录**：某些 ROM（如 ColorOS、HyperOS）可能不提供「部分选择」选项，而是直接给全量授权或拒绝。此时记录实际行为，并在设备矩阵中标注该 ROM 不支持部分授权。

## 场景 M-02：SAF 目录授权与撤销

**前置**：设备有可用的文件管理器。Android 11+ 不允许授权 Download 根目录，需选择其子目录。

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 首页点击「选择 Download 内的目录」 | 打开系统目录选择器 |
| 2 | 选择 Download 下的某个**子目录**（如 `Download/Docs`） | 返回应用 |
| 3 | 权限中心 → Downloads SAF | 显示「已授权」，并显示所选目录名 |
| 4 | 执行「安全体检」 | 扫描完成；Downloads 相关洞察包含该目录下的文件 |
| 5 | 进入「较早 Downloads」洞察页 | 能看到该目录下的文件列表；**不出现任何删除按钮**（只有预览/分享/定位） |
| 6 | 尝试对 Downloads 文件执行清理 | 无法进入清理计划（SAF 源被安全规则排除） |
| 7 | 回到系统设置 → 应用 → 权限 → 存储 → 移除已授权目录 | — |
| 8 | 重新打开 CleanGuard，执行扫描 | Downloads 不再被分析；权限中心显示「未授权」；**应用不崩溃** |

**通过标准**：步骤 5 无删除入口；步骤 6 无法选中；步骤 8 正常降级不崩溃。

**关键检查**：撤销授权后应用不得保留已失效目录的可读状态。

## 场景 M-03：回收站确认与取消

**前置**：授权媒体权限，设备有可清理的媒体项。

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 执行「安全体检」，进入结果页 | 展示分类与建议列表 |
| 2 | 选择若干 SAFE / REVIEW 项 | 默认仅 SAFE 被选中；REVIEW 需手动勾选 |
| 3 | 点击进入清理详情 | 显示每项的风险等级与允许动作 |
| 4 | 确认后 | 出现 **Android 系统回收站确认界面**（系统 UI，非应用自绘） |
| 5a | 在系统界面点**取消** | 应用返回；**不显示任何"已释放空间"**；项目仍在列表中；无崩溃 |
| 5b | 在系统界面点**确认** | 项目被移入系统回收站；显示实际处理结果 |
| 6 | 打开系统相册的回收站 | 能看到被移入的项目 |
| 7 | 回到应用「恢复中心」 | 显示本次清理记录；标注「系统回收站」类型 |
| 8 | 在恢复中心发起恢复 | 出现系统确认界面；确认后项目回到原位 |

**通过标准**：5a 取消后无虚假的空间释放提示；5b 确认后系统回收站可见；步骤 8 恢复有效。

**必须记录**：移入回收站后应用显示的「实际变化」数值。若应用显示了一个与实际不符的释放量，属于 P0 缺陷。

## 场景 M-04：删除不发生与风险规则生效

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 在结果页查找 DANGER 或 UNKNOWN 条目 | 若存在，应**不可勾选**，且不显示可用的处理动作 |
| 2 | 尝试通过重复文件页处理一个 DANGER 项 | 无法进入清理计划 |
| 3 | 在重复文件页 | 每个文件的复选框**默认全部未选中**；页面明确提示「默认没有选择任何文件」 |
| 4 | 观察重复文件页的视觉提示 | 「建议保留最新/最早」仅作为提示，**不得**自动改变任何复选框状态 |
| 5 | 尝试触发全局清理 | 应用**不提供**任何全局一键清理入口 |

**通过标准**：DANGER/UNKNOWN 不可选；REVIEW 默认不选中；不存在全局清理入口。

## 场景 M-05：进程被回收后的状态恢复

**前置**：已完成至少一次扫描，产生了历史数据。

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 完成一次「安全体检」 | 扫描成功，首页出现空间趋势 |
| 2 | 用系统设置或第三方工具**强制停止**应用 | 进程被杀死 |
| 3 | 重新打开应用 | 正常启动，无崩溃；上次扫描趋势仍在（本地持久化生效） |
| 4 | 执行第二次扫描 | 若媒体库无变化，应识别为增量扫描 |
| 5 | 锁屏 → 解锁 | 正常恢复，无崩溃 |
| 6 | 旋转屏幕（若设备支持） | 界面正常重建，无崩溃；无 ANR |
| 7 | 从最近任务划掉应用后重开 | 正常启动 |

**通过标准**：每一步均无崩溃、无 ANR；趋势数据在进程被杀后仍存在。

## 场景 M-07：长时运行稳定性

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 在有大数据集的设备上执行扫描 | 扫描完成，无 ANR |
| 2 | 连续执行 10 次扫描 | 每次均完成；数据库持续增长但不异常膨胀 |
| 3 | 进入「重复文件」页并停留 | 哈希计算完成；不出现 OOM；界面不卡死 |
| 4 | 观察内存占用（`adb shell dumpsys meminfo com.cleanguard.app`） | 扫描前后无持续增长趋势（观察 3 次快照） |
| 5 | 连续使用 30 分钟后返回首页 | 无异常；无 ANR |

**通过标准**：步骤 4 中，第三次快照的 Java heap 相对第一次的增长不呈持续线性上升。

**记录**：三次 `meminfo` 快照的 PSS / RSS / Java heap 数值。

## 场景 M-08：权限撤销后的降级与不崩溃

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 授予全部媒体权限并完成一次扫描 | 正常 |
| 2 | 在系统设置中撤销照片权限 | — |
| 3 | 回到应用 | 不崩溃；权限中心显示照片为「未授权」 |

**通过标准**：每一步都不崩溃；扫描是**部分降级**而非整体失败；提示文案与实际状态一致。

## 场景 M-09：下载目录中的 APK 识别

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 在授权的 Download 子目录中放入 1 – 2 个 `.apk` 文件 | — |
| 2 | 执行扫描并进入「APK 洞察」 | 能看到该 APK；显示包名、版本、versionCode |
| 3 | 观察安装状态显示 | 若已安装同版本显示「与已安装版本相同」；若包不可见显示「受 Android 包可见性限制，安装状态未知」——**不得误报为「未发现已安装版本」** |
| 4 | 在提示中查找「建议优先查看 · HIGH（不是安全等级）」 | 该建议的**风险等级仍为 REVIEW**，不得直接可处理 |

**通过标准**：步骤 3 的表述准确；步骤 4 的建议优先级不改变风险等级。

## 场景 M-12：ROM 定制行为（按需执行）

针对 HyperOS / ColorOS / MagicOS / OriginOS / One UI 各自执行以下检查：

| 步 | 操作 | 期望结果 |
|---|---|---|
| 1 | 检查 ROM 是否要求「后台弹出界面」权限 | 记录是否需要该权限才能让系统确认界面正常弹出 |
| 2 | 执行一次清理到系统确认界面 | 系统弹窗正常出现，未被 ROM 拦截或延迟 |
| 3 | 应用退到后台，观察 ROM 是否杀进程 | 记录被杀的时机；恢复后状态一致 |
| 4 | 检查 ROM 的「安装增强防护」/ 应用扫描提示 | 记录首次安装时是否出现额外确认步骤 |
| 5 | 检查 ROM 的电池优化白名单 | 记录是否需要加入白名单以保证系统确认界面可用 |

**通过标准**：每项 ROM 差异都被记录到 `OEM-DEVICE-VALIDATION-REPORT.md` 的对应小节。

## 执行后的动作

1. 逐条填写上面的结果表
2. 失败的场景 → 在 `BUG-TRACKER.md` 的「Active bugs」中新增条目，含复现步骤、根因、严重级别
3. 通过的场景 → 更新 `DEVICE-MATRIX.md` 对应行，把「Partial pass」细化为具体覆盖项
4. ROM 差异 → 追加到 `OEM-DEVICE-VALIDATION-REPORT.md`
5. 删除设备上的 `Pictures/CleanGuardManual/` 测试目录
6. 恢复 signed Release 构建到设备

---

## 与 R3 的关系

本脚本的手动场景与 R3 性能采集是两件事：

- 本脚本验证**功能正确性**与 OEM 兼容性，可在任意物理真机上执行
- R3 验证**性能基线**，需要特定设备档位与大数据集，且必须记录 Perfetto trace

R3 还需要 M-03、M-07 的行为配合，但性能数据必须由 `R3-PERFORMANCE-TEST-PLAN.md` 的规程单独采集。
